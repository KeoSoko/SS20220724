# TASK #5 — Workspace Subscription Inheritance (Deploy 1)

## Objective

Fix the broken multi-user workspace experience.

Today:

* Workspace members are checked against their own subscription.
* Accepting a workspace invite cancels the invitee's subscription.
* Members lose access even when the workspace owner is paying.

We are fixing this.

This deployment is intentionally limited to inheritance and access control.

Do NOT implement Team Plans, seat billing, Paystack changes, billing dashboards, invite limits, or any billing infrastructure.

---

# Scope

Implement only:

1. Workspace subscription inheritance
2. Remove auto-cancel on invite acceptance
3. Fail-closed owner lookup
4. Structured observability logging
5. Subscription status refresh improvements

No schema changes.

No Paystack changes.

No webhook changes.

No billing logic changes.

---

# Required Behaviour

## Owner Status Is Authoritative

Workspace owner subscription determines access for all members.

Examples:

Owner active
→ members active

Owner trial
→ members trial

Owner expired
→ members expired

Owner cancelled
→ members cancelled

Members inherit whatever status the owner has.

Ignore the member's own subscription for access decisions.

---

# Create getEffectiveSubscriptionStatus(userId)

Location:

server/subscription-middleware.ts

Create:

getEffectiveSubscriptionStatus(userId)

Logic:

1. Determine user's workspace.
2. Determine workspace owner.
3. If user is owner:

   * use their own subscription status.
4. If user is member:

   * use owner's subscription status.
5. If owner missing:

   * fail closed
   * deny access
   * emit critical log

DO NOT fall back to member subscription.

---

# Fail Closed When Owner Missing

If workspace owner cannot be found:

Return no access.

Emit:

[CRITICAL_WORKSPACE_OWNER_MISSING]
{
workspaceId,
userId,
ownerId
}

Do not silently continue.

Do not fall back.

---

# Wire Into Access Gates Only

Use getEffectiveSubscriptionStatus() only in:

* requireSubscription()
* checkFeatureAccess()

Do NOT modify:

billingService.getSubscriptionStatus()

The billing-service version remains user-specific.

It is used for billing lifecycle decisions and must stay unchanged.

---

# Remove Auto-Cancel Bug

Location:

POST /api/workspace/accept-invite

Remove the logic that:

* calls billingService.cancelSubscription(userId)
* cancels trial subscriptions
* cancels active subscriptions
* sets subscriptionCancelled flags

Delete this behaviour entirely.

Invite acceptance should:

* join workspace
* update membership
* stop

Nothing else.

No subscription cancellation.

No replacement logic.

# Structured Logging

{

}

[EFFECTIVE_SUBSCRIPTION_BLOCKED]
{
userId,
workspaceId,
ownerId,
ownerStatus,
memberStatus
}

When owner missing:

[CRITICAL_WORKSPACE_OWNER_MISSING]
{
workspaceId,
userId,
ownerId
}

Keep logs concise and structured.
