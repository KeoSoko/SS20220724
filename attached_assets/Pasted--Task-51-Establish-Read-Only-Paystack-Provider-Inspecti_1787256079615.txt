# CRITICAL PROVIDER SAFETY BOUNDARY

Paystack access for this task must be strictly read-only.

Permitted provider operations are limited to documented Paystack retrieval/listing operations required to inspect:

* customers;
* transactions;
* subscriptions;
* plans where necessary;
* invoices/transaction history where necessary to establish renewal results.

Before making any provider request, identify the exact Paystack endpoint and HTTP method.

Only provider operations that are demonstrably read-only may be used.

## Forbidden Paystack operations

Do NOT call any endpoint or SDK operation that can:

* initialize a transaction;
* charge an authorization;
* create a subscription;
* enable a subscription;
* disable a subscription;
* cancel a subscription;
* update a subscription;
* update a payment method;
* generate a management link;
* generate an update-subscription link;
* create a customer;
* update a customer;
* create/update a plan;
* refund a transaction;
* resend an invoice;
* retry a charge;
* debit an authorization;
* modify provider metadata.

No POST/PUT/PATCH/DELETE provider request is authorized unless you first prove that Paystack's documented contract treats that exact operation as read-only AND stop for review before calling it.

For this task, prefer GET-only provider access.

If an endpoint's side effects are uncertain:

**DO NOT CALL IT.**
