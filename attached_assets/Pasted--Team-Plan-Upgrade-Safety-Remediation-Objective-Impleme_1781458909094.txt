# Team Plan Upgrade Safety Remediation

## Objective

Implement the safest production path for Team Plan upgrades.

We have identified a billing risk:

Current one-click upgrades:

* Charge the stored authorization_code
* Update the local plan immediately
* Increase seat capacity immediately

But they do NOT:

* Disable the existing recurring Paystack subscription
* Create a replacement recurring subscription on the new Team Plan

Result:

At the next Paystack renewal, the webhook receives the OLD plan code and correctly reconciles the customer back to the old plan.

This can:

* Reduce seat capacity unexpectedly
* Under-charge customers
* Create billing confusion

We are fixing that now.

---

# Scope

Implement ONLY the immediate safety fix.

Do NOT build subscription retirement yet.

Do NOT build Paystack subscription migration yet.

Do NOT build reconciliation jobs.

Do NOT modify Team Plan pricing.

Do NOT modify seat enforcement.

Do NOT modify inheritance.

---

# Required Change

## Disable One-Click Upgrades

Current path:

POST /api/billing/upgrade

calls:

billingService.upgradeToPlanWithStoredAuth()

which performs:

* transaction.charge()
* local plan update

This path must no longer be used.

---

## New Behaviour

When an owner attempts to upgrade:

Return:

{
"needs_checkout": true
}

and route them through the existing Paystack checkout flow.

Use the same flow as a brand-new Team Plan purchase.

Do NOT perform:

* transaction.charge()
* local plan flips
* immediate subscription upgrades

The only valid upgrade path should be:

Owner clicks Upgrade
→ Paystack checkout
→ Successful payment
→ charge.success webhook
→ Deterministic plan resolution
→ Subscription activated on the correct Team Plan
