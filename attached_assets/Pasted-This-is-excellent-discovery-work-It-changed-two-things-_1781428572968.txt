What I Would Change in Task #5
Change 1: Fail Closed on Missing Owner

I would absolutely amend the task.

Originally:

Owner not found
→ fallback to member subscription

Now that you've proven:

0 orphaned workspaces today
orphaning is possible
owner_id has no FK
6 owners can potentially be deleted

I would change the rule to:

Owner not found
→ deny access
→ emit CRITICAL log
→ return explicit error

Example log:

[CRITICAL_WORKSPACE_OWNER_MISSING]
{
  workspaceId,
  userId,
  ownerId
}

This turns a data integrity issue into a visible operational issue instead of silently masking it.

Member Upgrade Visibility

This is the only place where I'd be careful not to over-engineer.

You discovered:

staleTime = 5 minutes
no polling
no focus refresh

For V1 I would not add polling.

I'd simply enable:

for subscription status.

That's enough that:

Owner upgrades
↓
Member clicks around
↓
Window focus changes
↓
Status refreshes

without introducing constant API traffic.
